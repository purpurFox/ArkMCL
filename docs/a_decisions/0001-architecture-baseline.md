# ADR-0001：启动器架构基线决策

- 状态：已接受
- 日期：2026-10-23
- 决策者：Mr. Fox
- 设计载体：`docs/a_decisions/0-现型.xlsx`
- 后续变更：存储路径以 `docs/a_decisions/0002-storage-layout.md` 为准。

## 背景

ArkMCL 是《Minecraft：Java 版》启动器，采用 Rust 后端 + Flutter 前端，架构效仿 MultiMC：实例目录化、组件化版本、共享元数据缓存、启动流水线。

架构设计阶段列出了 12 个待决问题，现已全部定稿。本文记录决策、边界与代价。

## 决策

### D-001 IPC：UDS + JSON-RPC

- 服务端在 `XDG_RUNTIME_DIR` 下创建 Unix domain socket，使用 JSON-RPC 2.0。
- 协议带版本号，握手时协商；不兼容时拒绝连接并返回明确错误。
- 启动进度等单向消息使用 JSON-RPC 通知，不使用轮询。
- 选择理由：Linux 优先、无需监听 TCP 端口、便于用 `socat`/`jq` 调试，CLI 与 GUI 共用同一客户端。

### D-002 元数据缓存：可变 TTL + 不可变永久 + 手动刷新

- **可变元数据**：版本清单、加载器版本列表、Java 运行时清单。默认 24h TTL；每次按需访问时发条件请求（ETag/If-Modified-Since）；用户手动刷新时忽略 TTL，强制请求。
- **不可变元数据**：单版本 JSON、资源索引、日志配置。按 id/hash 永久缓存；用户可手动重下覆盖；损坏时按校验和重建。
- **内容缓存**：库、natives、资源对象、客户端 jar、Java 运行时。按 SHA-1 寻址，不设 TTL，命中前校验，失败即删除重下。
- 网络失败时使用过期缓存并在 UI 标记 stale；无缓存时返回可操作的错误。
- 所有元数据都提供手动刷新入口；缓存目录遵循 XDG，可在设置中查看与清理。
- 缓存中不得出现账户令牌、密码或实例用户数据。

### D-003 凭据存储：系统密钥环，缺失时降级并警告

- 优先使用 Secret Service（通过 `keyring` 类库）。
- 密钥环不可用时，降级为受权限保护的加密文件，并在 UI 与日志中显式警告。
- 任何情况下不得将令牌写入普通配置文件、实例包或日志。

### D-004 Java：优先检测已有，缺失时提示用户下载

- 启动前扫描 PATH 与常见安装目录，校验主版本、架构与可执行性。
- 不满足要求时不静默下载，返回带下载指引的错误，由用户确认后下载。
- `JavaProvisioner` 保留为可选能力，仅在用户明确确认后使用。

### D-005 不使用数据库

- 全局设置、实例配置、组件链使用 JSON 文件 + 原子写（临时文件 + fsync + rename）。
- 元数据与下载内容放在缓存目录，可随时重建。
- 若未来实例数量或查询需求显著增长，再评估 SQLite；当前不引入 schema 迁移成本。

### D-006 下载源：支持镜像列表，官方源不可移除

- 设置中维护下载源列表，每项包含 id、基地址、是否官方、优先级。
- 官方源始终存在且不可删除；镜像失败时回退官方。
- 镜像仅作为传输层，所有文件仍必须通过 SHA-1 校验，校验失败即失败，不因镜像而放宽。

### D-007 Mod 依赖：完整解析

- 目标是完整解析 Fabric/Quilt/Forge/NeoForge 的 mod 依赖，并检测缺失依赖、版本冲突与循环依赖。
- 解析结果必须可解释：冲突需给出涉及的 mod、版本与约束来源。
- 实现可分阶段，但接口契约按完整解析设计，避免后续推倒重来。

### D-008 并发实例：可配置，默认 1

- 设置项 `max_concurrent_instances` 控制同时运行的实例数，默认 1，范围 1..=8。
- `LaunchService` 用信号量或等价机制强制执行，超出时返回明确错误而不是排队等待。

### D-009 更新：包管理器分发，GUI 仅提示

- 不自更新。Linux 侧通过发行版包管理器、Flatpak 或 AppImage 分发。
- GUI 只展示“有新版本可用”的提示与获取方式，不下载、不替换自身文件。

### D-010 日志：默认仅本地

- 启动日志、崩溃日志默认只写入本地实例目录。
- 仅在用户明确要求上传时才发送，且发送前展示内容范围；默认关闭任何自动上传。

### D-011 离线/外置登录：以正版账户为前提

- 仅当至少一个已登录的 Microsoft 账户拥有 Minecraft: Java Edition 时，才在 UI 中开放离线/外置登录入口。
- 该限制是产品策略与 UX 门槛，不是安全边界：本地程序无法真正阻止用户修改。实现上应如实说明这一点，不宣称“防破解”。

### D-012 Forge/NeoForge：优先解析安装 profile

- 优先读取官方安装器生成的版本 profile（库、主类、参数、处理器），从缓存或 Maven 获取。
- 仅在 profile 缺失或损坏时运行官方安装器；安装器在独立临时目录中执行，设置超时（默认 5 分钟）、限制可写范围、捕获 stdout/stderr。
- 安装完成后校验产物与 profile，再原子替换到实例；失败则保留日志并回滚，不留下半安装状态。
- NeoForge 复用同一流程，仅元数据源与安装器坐标不同。

## 对设计的影响

已同步到 `0-现型.xlsx`：

- 新增「缓存清单」页，列出 17 类数据的来源、位置、失效策略与校验方式。
- 新增 `DownloadSource`、`MirrorPolicy`，并在设置中增加 `max_concurrent_instances`。
- 新增 `ModDependencyResolver`，`ModService` 在扫描后调用依赖解析。
- `JavaService::ensure` 的契约改为“返回带下载指引的错误，不自动下载”。
- `AccountService` 增加 `can_use_offline_login` 策略检查。
- `MetaService` 增加 `refresh(force)`，承载手动刷新与条件请求。
- `ComponentForge` 增加 `ensure_profile`，落实 profile 优先策略。
- 相关类状态标记为“已评审”。

## 后果

正面：

- IPC、存储、凭据与更新策略确定后，服务端与 GUI 的边界可以稳定下来。
- 下载校验与官方源不可移除，降低镜像带来的供应链风险。
- 完整依赖解析的接口先定，避免后续为兼容做破坏性改动。
- 缓存策略区分可变与不可变，既避免频繁请求，又允许用户强制刷新。

代价与限制：

- 无数据库意味着复杂查询需要全量加载 JSON；实例数量大时需重新评估。
- 密钥环降级路径需要额外的文件加密与权限处理，且必须做好警告，避免用户误以为安全。
- 完整依赖解析工作量大，需要为各加载器实现元数据读取器。
- 不自更新意味着版本分发依赖打包与仓库维护。
- Forge/NeoForge 安装器仍可能因网络、Java 版本或签名问题失败，需要可诊断的日志与回滚。
